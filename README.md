# ❤️ CardioXAI — Heart Disease Prediction with Explainable AI (Flask edition)

A full-stack web app: **Flask + Python** backend, **HTML/CSS/JS** frontend,
**SQLite** database — built for the UCI Cleveland Heart Disease dataset, with
SHAP and LIME explanations rendered as interactive charts.

## Features
- **Login / registration** with hashed passwords (Werkzeug). Every prediction
  and every uploaded report is scoped to `user_id` in SQLite and checked on
  every read — one account can never see another account's data.
- **English / Tamil (தமிழ்)** language switcher in the sidebar. Preference is
  saved per-account. Login, register, and the predict page are fully
  translated; the symptoms/history/compare pages currently render their
  longer body copy in English only (see "Known limitations" below).
- **Scan & test report uploads** (`/reports`) — upload images or PDFs of ECGs,
  angiograms, blood tests, etc. Files are stored outside `static/` and served
  through a route that checks file ownership before returning anything.
- **Personalized plan** shown after each prediction — a plain-language risk
  stage, alternate options to raise with a doctor, and a heart-healthy diet
  plan (with South Indian food examples), plus a rotating positive quote.
  This is educational content, not a prescription.
- **"Ask AI to explain" button** — turns the raw SHAP numbers into a short,
  readable paragraph. Works offline out of the box using a deterministic,
  rule-based generator (`llm_explainer.py`); if you set an `ANTHROPIC_API_KEY`
  environment variable, it automatically upgrades to a real Claude-written
  explanation instead, and silently falls back to the offline version if the
  API call ever fails — so a live demo can never break because of a bad wifi
  connection. See "AI explainer" below.
- **Augmented training data** — see "About the training data" below.

## How to run

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Run the app
```bash
python app.py
```

The **first time** you run it, there are no trained models yet, so it will
automatically train all 4 models (takes ~1–2 minutes) before starting the
server. Every run after that starts instantly using the saved models.

You'll see:
```
* Running on http://127.0.0.1:5000
```

Open **http://127.0.0.1:5000** in your browser. You'll be asked to register
an account before you can use the tool — this is what keeps each person's
predictions, uploads, and history private to them.

### 3. Use it
- **Register / Log in** — required before any other page. Pick English or
  Tamil from the sidebar at any time; your choice is remembered.
- **Predict** — enter patient values, pick a model, click "Check my risk."
  You'll see the risk result, two interactive charts (SHAP + LIME) explaining
  *why*, and a personalized plan (risk stage, alternate options to discuss
  with a doctor, a diet plan, and a quote).
- **My Reports** — upload photos/PDFs of your own ECG, angiogram, or blood
  test reports. Only your own account can view or delete them.
- **History** — every prediction is saved and listed here per-account. You
  can clear your own history with the "Clear history" button.
- **Model Comparison** — a metrics table and chart comparing all 4 trained
  models (Logistic Regression, Random Forest, XGBoost, Neural Network).

## AI explainer (the "Ask AI to explain" button)

After a prediction, the SHAP and LIME charts show *which* features mattered,
but reading a bar chart of feature-importance numbers isn't something most
patients can do. The **"Ask AI to explain my result"** button on the predict
page turns that same data into a short paragraph in plain English or Tamil.

It runs in one of two modes, chosen automatically — the UI labels which one
produced the answer, so nobody mistakes it for a doctor's note:

- **Rule-based (offline)** — the default. `llm_explainer.py` ranks the SHAP
  contributions, looks up a human phrase for each top factor together with
  the patient's own value (e.g. *"your cholesterol level of 250 mg/dl"*),
  and assembles a paragraph from a template. No API key, no internet, no
  cost, and it can't go down mid-demo.
- **AI-generated (Claude)** — an optional upgrade. Set an
  `ANTHROPIC_API_KEY` environment variable before running the app:
  ```bash
  export ANTHROPIC_API_KEY=your-key-here   # macOS/Linux
  set ANTHROPIC_API_KEY=your-key-here      # Windows (cmd)
  python app.py
  ```
  With the key set, the same structured data (probability, top SHAP factors,
  the patient's actual values) is sent to Claude, which writes a warmer,
  more natural paragraph. If that API call ever fails for any reason — no
  network, rate limit, timeout — the app **silently falls back** to the
  rule-based version instead of showing an error. This is a genuine
  best-effort upgrade, never a hard dependency.

No patient-identifying information is sent in either mode — only the
model's own numeric inputs and its output.

## About the training data

The UCI Cleveland Heart Disease dataset (`data/heart.csv`) has ~300 real
patient records — that's the standard, well-known public dataset this kind
of project is built on, and this environment has no internet access or
license to pull in additional real patient records from elsewhere.

To still give the models more examples to learn from, `train_models.py`
bootstrap-resamples the **training split only** and adds small (±3%),
clinically-plausible Gaussian jitter to continuous fields (age, blood
pressure, cholesterol, max heart rate, ST depression), clipped to realistic
ranges. This expands ~240 real training rows to roughly 950–1000 rows the
model actually trains on. **The held-out test split is never touched** —
it's always 100% real, original rows — so the accuracy/precision/recall/F1/
ROC-AUC numbers in `models/results.json` remain an honest measure of
performance on real data. `results.json["dataset_info"]` records the exact
row counts and a note about how the extra rows were generated, so this is
never hidden from anyone reading the metadata.

This is a standard data-augmentation technique (similar in spirit to SMOTE),
not a source of new medical knowledge — it doesn't invent new categorical
facts about patients, just varies existing patients' numeric readings
slightly to reduce overfitting to a small dataset.

## Why XGBoost is saved differently

Earlier versions of this project saved all models with `joblib`/pickle,
which caused `XGBoostError: input stream corrupted` when the pickle was made
with a different xgboost version than the one installed locally. This version
saves XGBoost using its own native `.json` format
(`model.save_model(...)` / `.load_model(...)`), which is stable across
versions. If you ever hit a similar error with the other models, just delete
everything inside `models/` and restart `app.py` — it will retrain
automatically using whatever library versions are installed on your machine.

## Tech stack
- **Backend:** Flask, scikit-learn, XGBoost, SHAP, LIME, Werkzeug (auth + secure uploads)
- **Frontend:** HTML, CSS (custom design system, no framework), vanilla JS, Chart.js (via CDN)
- **Database:** SQLite (via Python's built-in `sqlite3`)

## Known limitations / good next steps
- The symptoms, history, and model-comparison pages still show their body
  copy in English only — the sidebar/nav and predict page are fully Tamil,
  but translating the longer educational paragraphs on those pages is a
  good next step if full-site Tamil coverage matters to you.
- Training-data "augmentation" is a statistical technique, not new real
  patient data — see above. If real additional labeled data becomes
  available, drop it into `data/heart.csv` (same columns) and delete
  everything in `models/` to retrain on it directly.
- Uploaded reports are stored as plain files on disk (not encrypted at
  rest). Fine for a learning project; add encryption-at-rest or object
  storage (e.g. S3 with per-object ACLs) before using this with real patient
  documents in production.
- Deploy with Gunicorn + a real WSGI/HTTPS setup instead of the Flask dev
  server before showing this to real users.
